# Сборка DMG

Установщик содержит универсальное приложение для Apple Silicon и Intel,
ссылку на `/Applications` и инструкцию по первому запуску. Минимальная macOS — 14.0.
Сборка для распространения не заменяет `~/Applications/Ясно.app` и локальную
сборку `dist/Ясно.app`.

## Повторная сборка

На этом Mac установлен Developer ID Application для команды `NJXU5X745X`.
Закрытый ключ хранится в Связке ключей; сертификаты и API-ключи не входят в DMG.
Профиль нотарификации в Связке ключей называется `yasno-distribution`.

```sh
YASNO_NOTARY_PROFILE=yasno-distribution ./scripts/package-dmg.sh
```

Скрипт собирает arm64 и x86_64, объединяет их через `lipo`, подписывает приложение
с Hardened Runtime и временной меткой Apple, отправляет его на нотарификацию,
прикрепляет билет к приложению, создаёт и подписывает DMG, затем отдельно
нотарифицирует DMG и прикрепляет его билет. Только после успешных проверок
готовый файл появляется в `dist`. Рядом сохраняется контрольная сумма SHA-256.

Если доступно несколько сертификатов Developer ID Application, укажите нужный
через `YASNO_SIGNING_IDENTITY`. Данные нотарификации берутся из Связки ключей,
они не записываются в исходники. Без `YASNO_NOTARY_PROFILE` скрипт создаёт файл
с окончанием `-signed.dmg`; он подписан, но не прошёл нотарификацию Apple.

Для оформления Finder используются `ds-store` и `mac-alias` с закреплёнными
версиями из `scripts/dmg-requirements.txt`. Они устанавливаются в отдельную
сборочную среду `.build/dmg-tools` и не нужны пользователю приложения.

## Долгая проверка Apple

Сведения запроса сохраняются сразу после загрузки в
`.build/distribution/pending-submission.json`: идентификатор, профиль Связки
ключей и путь к точной подписанной копии приложения в отдельном каталоге
`release-<версия>.*`. Если Apple продолжает обработку, ожидание можно
возобновить без повторной отправки приложения:

```sh
./scripts/resume-notarization.sh
```

Этот скрипт ожидает существующий запрос до семи дней, затем завершает упаковку
и нотарификацию DMG. При отказе Apple или ошибке он останавливается, сохраняя
описание в `dist/Нотарификация.txt`. Проверка Apple продолжается во время сна
Mac; локальное завершение сборки ожидает пробуждения. Фоновая задача не
устанавливает автозапуск и после перезагрузки требует повторного запуска.
Журнал фонового запуска: `.build/distribution/notarization-background.log`.

## Проверка

```sh
hdiutil verify dist/Yasno-0.1.6-universal-notarized.dmg
xcrun stapler validate dist/Yasno-0.1.6-universal-notarized.dmg
spctl --assess --type open --context context:primary-signature --verbose=2 \
    dist/Yasno-0.1.6-universal-notarized.dmg
```

После монтирования также проверяются подпись и билет вложенного приложения.
Диагностика `Contents/MacOS/Yasno --diagnose` позволяет проверить загрузку
словарей без запуска второго перехватчика клавиатуры. На этом Mac Intel-срез
дополнительно проверяется через Rosetta (`arch -x86_64 ... --diagnose`).

## Автообновление

Сборка с сайта (DMG) каждый день в 21:00 по местному времени запрашивает последний
выпуск `mavesr/yasno` на GitHub. Если Mac спал или Ясно не было запущено, проверка
выполняется через пять минут после запуска или пробуждения. Флажок «Обновлять
автоматически» в окне программы отключает расписание, кнопка «Проверить сейчас» и
пункт меню «Проверить обновления» запускают проверку сразу.

Новая версия устанавливается без вопросов, только если:

- архив `Yasno-<версия>-universal.zip` из выпуска `v<версия>` (не черновик и не
  предварительный) содержит ровно одно приложение с той же версией;
- приложение удовлетворяет designated requirement запущенной копии: тот же
  идентификатор `local.yasno.switcher` и тот же сертификат Developer ID команды
  `NJXU5X745X`. Именно это требование macOS сохранила вместе с разрешениями
  «Универсальный доступ» и «Мониторинг ввода», поэтому повторного запроса нет;
- приложение нотарифицировано Apple;
- запущенная копия подписана Developer ID и лежит в папке, доступной для записи,
  а не во временном пути App Translocation.

Замена выполняется атомарно на месте (`/Applications/Ясно.app` остаётся тем же
путём), затем Ясно перезапускается. Локальная сборка с Apple Development и
версия из App Store (в ней нет ключа `YasnoUpdateRepository`) не обновляются.

### Публикация выпуска

```sh
YASNO_NOTARY_PROFILE=yasno-distribution ./scripts/package-dmg.sh
./scripts/publish-release.sh
```

`package-dmg.sh` после прикрепления билета Apple кладёт в `dist` архив
`Yasno-<версия>-universal.zip`. `publish-release.sh` проверяет его так же, как
программа (Developer ID, нотарификация, версия, репозиторий обновлений), и через
`gh release create` публикует выпуск `v<версия>` с архивом и DMG. Версию в
`scripts/build.sh` нужно повышать перед каждым выпуском, иначе обновление не
будет предложено.
