# Диагностика ввода

Есть на Mac (с 0.2.28), Linux (с 0.1.3) и Windows (с 0.2.1). Формат журнала общий; различия описаны в конце.

## macOS

Если в каком-то поле Ясно не переключает слова:

1. Меню Ясно → «Включить диагностику ввода» → «Включить».
2. Напечатайте в этом поле несколько слов не в той раскладке, с пробелом после каждого.
3. Меню Ясно → «Выключить диагностику ✓». Сама выключится через 30 минут.

Журнал сохраняется в `~/Library/Application Support/Yasno/InputDiagnostics/queue/`
(«Настройки диагностики…» → «Показать журналы»). Если в настройках указаны приватный
репозиторий (по умолчанию `mavesr/yasno-diagnostics-logs`) и fine-grained токен с доступом
только к нему (Contents: Read and write), журнал отправляется туда как
`logs/<сессия>.jsonl`. В публичный репозиторий Ясно ничего не отправит.
Отправленный журнал хранится на Mac ещё неделю в папке `sent/`.

## Что пишется

Одна строка JSON на событие. Первая строка — `meta` (версии, начало сессии), вторая —
`session` (состояние Ясно: раскладки, разрешения, исключённые приложения), последняя —
итог (`closed_reason`, число событий).

| event | когда |
|---|---|
| `app` | активировалось приложение (bundle id, версия) |
| `focus` | фокус перешёл на новое поле; `field` — как его видит Accessibility |
| `focus_window` | сменилось только окно |
| `monitor` | Ясно начало или перестало следить за клавиатурой, со статусом |
| `word` | слово закончено пробелом: текст, раскладка, pid |
| `word_dropped` | слово сброшено до конца (`reason`: клик, смена приложения, мёртвая клавиша…) |
| `no_suggestion` | словари не нашли другой раскладки (`reason`, `context_tail`) |
| `skipped` | исправление не делалось (`reason`) |
| `no_field` | Ясно не нашло поле ввода: `system_focus`, `app_focus`, `typing_app_pid` |
| `no_caret` | поле есть, но текста перед кареткой не видно: `field` (selection, characters, before_caret), `expected_before_caret` |
| `canvas` | поле без текста (холст), исправление клавишами |
| `edit` | попытка замены: `result` (success, unsupported, failed, stale); при неудаче — `field` |
| `layout_not_selected` | текст исправлен, раскладку переключить не удалось |

`field` содержит роль и подроль, роли предков, атрибуты, что можно менять
(`settable`), выделение и до 80 символов перед кареткой.

Пароли не пишутся: пока macOS сообщает о защищённом вводе, событий нет вовсе; в поле,
похожем на пароль (подроль, класс или идентификатор с secure, pass, token, otp…, или
AXProtectedContent), текст поля и набранные слова заменяются на
`not recorded: field may hold a secret`.

## Как читать

`jq -c 'select(.event != "app")' logs/<сессия>.jsonl` — обычно хватает найти первое слово
`word` в нужном поле и следующее за ним `no_field`, `no_caret`, `no_suggestion`, `skipped`
или `edit` с неуспешным `result`.

## Linux

Значок Ясно в трее → «Включить диагностику ввода», или окно Ясно → «Диагностика…».
Журналы лежат в `~/.local/state/yasno/diagnostics/queue/` и уходят в тот же приватный
репозиторий как `logs/linux/<сессия>.jsonl`. Токен хранится в `~/.config/yasno/diagnostic-token`
(доступ только владельцу), отправляет его системный Python.

Linux не показывает Ясно поле ввода, поэтому событий `focus`, `no_field`, `no_caret` нет.
Вместо них: `app` (окно, которое получает клавиши), `devices` (какие клавиатуры Ясно читает,
какие заняты другой программой, например xremap), `layouts`, `stall`. В `edit` есть
`layout_after` — раскладка после замены. Пароли распознаются только в окнах самой системы
(вход, разблокировка), поэтому в браузере во время диагностики пароли вводить не надо — об
этом предупреждает окно включения.

## Windows

Значок Ясно в трее → «Включить диагностику ввода», в окне настроек — «Диагностика…».
Журналы лежат в `%LOCALAPPDATA%\Yasno\Diagnostics\queue\`, отправляются как
`logs/windows/<сессия>.jsonl`. Токен хранится зашифрованным для текущего пользователя (DPAPI).
`focus` описывает окно с фокусом: класс окна, процесс, есть ли каретка и поле пароля
(ES_PASSWORD) — в таком поле слова не записываются.
